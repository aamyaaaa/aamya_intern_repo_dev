## Reflection

### What challenges did you face while setting up i18next?

The main challenge was understanding how i18next and react-i18next work together. I wasn’t sure where to put the configuration file or why I needed to import it in the main entry file. I also had to make sure the translation keys in the component exactly matched the ones in the i18n configuration, otherwise nothing would show. Once I understood the flow, it became much easier.

### Why is it important to use a library like i18next instead of manually handling translations?

Manually doing translations using if/else or hard-coded objects becomes messy and hard to maintain as the app grows. A library like i18next keeps all translations organized in one place, supports multiple languages easily, handles switching at runtime, and includes features like fallback languages and interpolation. It makes the app scalable and much easier to manage.

### How would you handle dynamic content (e.g., user-generated text) in a multilingual app?

i18next works best for UI text that we control. Dynamic content from users can be written in any language, so I would store it as-is and display it directly. If the app needs translations for user-generated text, that should be handled separately using a backend service or translation API, not inside i18next.
