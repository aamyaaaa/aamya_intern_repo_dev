# Git & Pull Request Understanding (Issue #53)

## 1. What is a Pull Request (PR)?

A Pull Request (PR) is a request to merge changes from one branch into another (usually from a feature branch into `main`). It allows others to review the changes before they are merged.

## 2. Why are PRs important in a team workflow?

- They allow code review and catch mistakes early.
- They encourage collaboration and discussion.
- They prevent direct changes to `main`, protecting stability.
- They become documentation of why and how changes were made.

## 3. What makes a well-structured PR?

- A clear title describing the change.
- A detailed description including the **what** and **why**.
- Small focused changes that are easy to review.
- Links to related issues (e.g., `Fixes #53`).
- Clean commit history with meaningful commit messages.

## 4. Reflection from reviewing an open-source PR

- Reviewers gave feedback constructively.
- Author explained decisions clearly.
- Automated checks ensured the code was safe.
- PR was small and easy to understand.
- Maintainers approved once discussion was resolved.

## 5. What I learned

PRs are not only about pushing code — they are about communication, collaboration, and improving the project together.
